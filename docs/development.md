# LLM Radar 开发手册

按 `llm-radar`、`admin-web`、`worker` 与 `web` 的顺序交付。先在本机用 CLI 跑通一个官方定价页，再扩展到第三方报价和评测。管理 API 契约确定后即可开始前端开发，无需等待 D1 或公开站点上线。应用目录和依赖方向见 [项目架构](architecture.md)，完整字段约束与恢复策略见 [实施方案](../plan.md)。

## 开发里程碑

| 顺序 | 实现内容 | 完成时应能演示 |
|---|---|---|
| 1 · `llm-radar` 最小采集 | Python 包、CLI、公共与本地迁移、来源导入、首个价格适配器、raw、SQLite 与 outbox | 从空目录初始化，导入并启用一个真实官方入口，运行一次取得带出处的报价；再次抓取相同响应，只更新观测时间 |
| 2 · 来源与评测 | 可信第三方价格入口、评测入口、指标登记、模型映射、修订、样本预览和回退规则 | 官方过期后选中有标注的第三方，恢复后切回；一个评测结果可定位到模型版本、指标版本和原报告 |
| 3 · NAS 常驻运行 | 内置调度、互斥、补抓、状态、备份、镜像、飞牛挂载；确定管理 API 的样例 | 不配置 D1 也可连续采集；重建容器后保留配置、历史、raw 与队列；CLI 查得到本次抓取成功但尚未同步 |
| 4 · `admin-web` 与本地 API | Python 管理路由、React 管理页、单镜像打包；同步发送器可并行实现 | 从浏览器新增停用来源、预览、启用、立即采集和查看结果；可处理待核对评测并调整每日抓取时间 |
| 5 · D1 对齐 | 按序重试、公开字段投影、对账、空库重建和旧备份恢复 | 用独立开发 D1 演练响应丢失、断网补发、快照重建；核对记录数和内容均一致 |
| 6 · `worker` 与 `web` | Hono 只读查询，公开模型列表、报价历史、评测详情 | 页面标明出处和回退原因，可按同一标准版本比较评测，并能追到原报告 |

## 1. 先完成一条真实采集链路

1. 在 `apps/llm-radar/pyproject.toml` 注册 `llm-radar = "llm_radar.cli:main"`，将 `src/llm_radar` 安装为包。应用从 `LLM_RADAR_DATA_DIR` 和 `LLM_RADAR_BACKUP_DIR` 取路径。开发目录与飞牛运行目录使用同一逻辑。
2. 首个公共迁移建立来源、模型、报价、汇率和价格历史；本地迁移建立私有配置、来源映射、运行、outbox 与同步位置。所有连接启用外键，迁移成功才推进版本。内置来源用固定 `source_id` 导入，重复导入保留已有审核和启停状态。
3. 选择一个能够独立核实原币、每百万 token 单位和适用档位的官方页面。在 `tests/fixtures/<source>/` 留下脱敏原始页、预期记录和分页结束证据；把已核实的公开元信息与适配器名登记到 `config/default-sources.json`。实施前尚未选定实际厂商或 endpoint。
4. 实现来源预览，然后让 `run-once` 使用同一个解析与校验入口。每页先写临时文件再原子落盘。分别记录运行 ID、来源 ID、页序、尝试次数、适配器版本与内容 hash；保存公开证据 URL 时剔除认证参数。
5. 网络和解析结束后，按来源开短事务。首次见到报价时写模型、报价和首条价格事件；再次抓到相同四项价格只更新 `last_seen_at`，差异才追加事件。把相关公开变更按依赖顺序写进 outbox，再提交。金额计算用 `Decimal`，JSON 传整数字符串，区分免费 `0` 和缺失 `null`。

开发时从 `apps/llm-radar/` 开始。以下为首个里程碑应交付的命令，当前仓库仍处于设计阶段：

```sh
uv sync --frozen
export LLM_RADAR_DATA_DIR="$PWD/.local/data"
export LLM_RADAR_BACKUP_DIR="$PWD/.local/backup"
uv run llm-radar sources import-defaults
uv run llm-radar sources export
```

用 `sources preview` 检查导出配置中的目标入口，再通过 `sources import` 显式启用；随后运行 `uv run llm-radar run-once` 和 `uv run llm-radar status`。本地开发数据及真实响应加入忽略规则。首个里程碑的完成证据是原始页、SQLite 中的价格事件以及带相同实体 ID 的待同步行。

## 2. 实现适配器与来源管理

| 契约 | 必需内容 | 使用方 |
|---|---|---|
| 来源配置 | 稳定 ID、`kind`、`source_class`、厂商范围、公开出处、优先级与有效期；私有部分含适配器、请求 URL、映射参数和 `secret_ref` | CLI 导入、管理表单和采集器共用一套配置校验 |
| `ParseResult` | 来源、用途、范围、完整性及证据、警告与错误；按用途携带报价或评测记录 | 预览读取结果；正式运行经规范化后入库 |
| 报价记录 | 源站模型键、提供商、模式、上下文范围、原币种、计价单位、输入/输出/缓存原值、证据 URL | 校验模型与报价维度；仅在同一可比档位内选择候选 |
| 评测记录 | 原报告结果键、模型原标签、标准/版本/指标、分数、单位、条件、实际评测方、原报告链接、可空的测评日期 | 匹配明确后写入评测表；模型或指标不明确时进入 NAS 待核对 |

来源、标准和模型映射是三个独立的编辑对象。举例：一个机构榜单新加了 `code-repair / v2 / pass_rate` 列，值为 `82.5`，原报告标注单位 `%`。先登记该版本的指标、方向和范围 `[0,100]`，再在榜单配置中映射该列、模型列和测试条件。若某行只写模型系列名，预览应显示原标签和“待确认版本”；其余明确行可以发布。管理员确认映射后，在一个事务中生成结果、记录审核并入队。再次采到 `82.5` 不增加修订；同一报告、模型和条件改成 `83.0` 才追加修订。另一个站转载时保留其出处，并按原报告、评测方和原结果键识别同一次测量。

为适配器提供一份正常样本和与该来源有关的失败样本：分页缺页、字段改名、计价单位变化或评测条件缺失。`empty`、`incomplete`、`error` 均保留旧业务数据。只有完整且非空的定价目录可以增加缺失次数；连续三次未出现可标记疑似下架，确认下架需单独记录管理员操作。评测缺榜只影响该条测量的可见信息。

## 3. 常驻服务与本地存储

- **触发与互斥。** `serve` 启动时恢复中断运行，检查今天的计划日期；默认北京时间 09:00，错过时只补当天。手动抓取、管理页面和调度器共享抓取锁；已有抓取时返回正在运行的 `run_id`。长任务不占用 HTTP 请求线程或 SQLite 写事务。同步单独持有发送锁。
- **一致性。** 每次抓取记录使用的来源配置版本；应用来源结果前检查该版本及启用状态。若采集过程中管理员改变配置，保留 raw 和该次运行记录，放弃旧版本的业务写入，下轮按新配置采集。这样管理员撤销授权后，旧任务不会把它改回去。
- **空间和关机。** 写入下一页之前检查预留空间。空间不足时记录来源失败并停止新抓取。收到 SIGTERM 后停止接收任务，已提交事务保留；下次启动将超出宽限时间的遗留运行标记 `abandoned`。按日清理运行已结束且超过 7 天的 raw。
- **备份。** 使用 SQLite backup API 向 `/backup` 写临时副本，成功完成后再转为正式文件并轮换最近 7 份。开发验收直接从一个副本打开数据库，核对来源配置、历史和积压。飞牛环境还需验证重建容器后的宿主机挂载。

## 4. 管理页面与本地 HTTP 接口

首页先回答三个问题：今天抓了吗，哪些来源需要处理，云端还有多少记录没收到。第一版设置四个页面：**状态与运行、来源、评测核对、调度设置**。来源页同时承载新建、预览、授权和停用；评测核对页可登记指标并处理原始标签映射。页面显示服务返回的判定与原因。

以下路径均以 `/admin/api/v1` 为前缀，仅在启用 NAS 管理功能时开放。建议首版使用单管理员令牌，通过 `runtime.env` 配置，页面在会话内存中持有令牌并使用 `Authorization: Bearer`；涉及凭据的局域网访问经 NAS 的 HTTPS 入口。API 校验身份，写请求校验允许的来源。表单只显示凭据引用，返回体及日志均脱敏。

| 请求 | 主要输入 | 成功返回与副作用 |
|---|---|---|
| `GET /status`、`GET /runs/{id}` | 无，或运行 ID | 最近抓取、备份、同步时间，积压数和最早时间，阻塞原因；运行详情附每个来源的结果、页数和错误 |
| `POST /runs` | 可选 `source_id`，缺省表示所有已启用入口 | `202` 和 `run_id`；前端轮询运行详情。已有抓取返回 `409` 和当前 ID |
| `GET /sources`、`GET /sources/{id}` | 可选用途与启用状态 | 来源及当前配置版本，最近核实时间、连续失败和可编辑的非敏感映射 |
| `POST /sources`、`PATCH /sources/{id}` | 新配置；更新另附当前 `revision` 和变更原因 | 新建 `201`，默认停用；修改 `200` 并递增版本。按公开字段入队，同时写本地审计 |
| `POST /sources/{id}/preview` | 待预览配置，可选该来源已保存的样本 ID | 返回命中字段、单位、完整性、待核对行及错误位置；支持用本地样本回放或按限额试抓，均不更新正式报价、运行缺失次数或 outbox |
| `PATCH /sources/{id}`（审核） | `revision`、`enabled` 或 `fallback_approved`、原因 | 服务校验用途、厂商范围与可比依据；启用与批准回退是两个可分别撤销的动作 |
| `GET /metrics`、`POST /metrics` | 标准标识、版本、指标、单位、方向、方法链接 | 查询已有定义，或创建新版本，返回 `metric_id` 并加入同步队列 |
| `GET /reviews`、`POST /reviews/{id}/resolve` | 待核对状态；提交确认的 `model_id`、`metric_id` 和原因 | 一次事务内处理该行并记录决策；重复确认同一决策返回既有结果。可用 `GET /models?query=…` 寻找本地模型版本 |
| `GET /settings/schedule`、`PATCH /settings/schedule` | 本地每日时间 `HH:MM`、版本 | 返回 `Asia/Shanghai`、下一次预计运行时间及新版本；重启后继续使用已保存配置 |
| `POST /sync/retry` | 无 | 唤醒同一个发送任务，返回当前同步状态；未配置 D1 时给出可读原因 |

**前后端联调例子。** 管理员保存一个待启用入口，取得 `source_id` 和 `revision=3`。预览发现“缓存价为空”，页面应显示“未提供”，而非 `0`。核实原文后提交 `PATCH /sources/{id}`，请求体为 `{"revision":3,"enabled":true,"reason":"原始计价单位已核对"}`。若另一标签页已保存版本 4，服务在同一事务中检查版本并返回 `409`，前端重新加载差异。字段错误用 `422` 和 `fields` 定位，身份无效返回 `401`，记录不存在返回 `404`。错误统一含 `code` 和用户可读的 `message`。

先用契约样例完成页面的加载、空数据、失败和冲突状态，再接本地 API。Vite 开发代理只代理 `/admin/api/v1`；发布时先构建 `admin-web/dist`，由 Python 同源托管，静态页面路由回退必须排除 API 路径。启用配置和镜像打包见 [项目架构](architecture.md)。

## 5. 同步与公开端交接

1. 本地事务按外键依赖写 `sync_outbox`。发送器按 `seq` 读取最早一项；网络和限流退避，鉴权或迁移错误停止推进。D1 成功且 SQL 结果成功后，在本地事务内更新 `sync_state` 和删除已确认项。响应丢失时重发原 ID；可变行按主键更新，不可变事件按 ID 去重。
2. `status` 分开记录抓取与发送结果。验收时在写入 D1 后、确认本地前中断发送，重启后检查历史只出现一次。恢复旧 NAS 备份时先暂停自动发送，保全 D1 较新内容；空库重建使用同一快照的高水位、行数和按主键排序的内容摘要。具体切换顺序以 `plan.md` 第八节为准。
3. Worker 阶段先用选价样例实现三个读取接口：模型当前价、某报价的历史、某模型的评测。返回原币原值、换算日期、来源、参考价原因或评测条件。公开 Web 最后对接；同一报价的历史曲线始终使用一个 `offer_id`。管理员的配置更改通过同步到达 D1，公开站点无需访问 NAS。

## 6. 交付前的验收记录

| 场景 | 观察位置 | 通过条件 |
|---|---|---|
| 官网临时失败 → 过期 → 恢复 | 来源详情、固定时钟的选价样例、`price_history` | 依次看到近期官方价、带出处的获准参考价、官方价；展示切换未产生调价事件 |
| 榜单新增标准、模糊模型和改分 | 预览、评测核对页、SQLite | 新指标通过配置接入；模糊行保留原标签；核对后发布；原分和修订均可追溯 |
| 手动与定时抓取重叠 | CLI、管理页、运行表 | 只有一个活动抓取，第二个入口能定位到已有运行；重启补抓也遵循当天去重 |
| 管理配置并发修改 | 两个浏览器标签页、审计记录 | 旧版本写入返回冲突，授权变更有原因，浏览器和 D1 都看不到源站密钥 |
| 飞牛换镜像、磁盘不足 | 宿主机目录、管理状态 | 重建后原库和 raw 可读；抓取因空间不足停止时保留上一轮完整数据 |
| 断网与恢复 | 本地 outbox、D1 开发库、备份目录 | 断网仍可采集，恢复后按序补齐；用备份恢复并完成一次空 D1 重建核对 |

发布 NAS 镜像前按 `plan.md` 第十四节完成双架构构建与固定版本发布。公开 Worker 与 Web 在其独立交付阶段部署。开发机上的 fixture/临时库、真实来源的人工核验、飞牛设备上的重建记录分别作为对应里程碑的验收依据。
